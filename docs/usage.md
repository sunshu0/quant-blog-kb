# qbkb 使用说明（给不熟悉命令行的人）

qbkb 会把量化机构博客上有价值的文章抓下来、打分筛选、翻译成中文，存成一个本地的 Markdown 知识库。
日常使用只需要一个**本地网页控制台**：双击启动，在浏览器里浏览文章、点按钮运行、看哪些文章需要处理、改设置。

> 控制台只在你自己的电脑上运行（地址是 `http://127.0.0.1:8790`），别人访问不到；关掉启动时弹出的黑色窗口，控制台就停了。

---

## 1. 安装（只做一次，三步）

1. **安装 uv**（管理 Python 的小工具）：打开"开始"菜单搜索 PowerShell，打开后粘贴下面这行，回车：

   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```

   装完**关掉 PowerShell 再打开一次**。
2. **下载代码**：在 GitHub 页面点 Code → Download ZIP，解压到一个文件夹（例如 `D:\qbkb`）；会用 git 的话 `git clone` 也可以。
3. **准备环境**：在 PowerShell 里进入这个文件夹，运行一次 `uv sync`（会自动下载 Python 和依赖，几分钟）：

   ```powershell
   cd D:\qbkb
   uv sync
   ```

## 2. 启动

- 双击 `scripts\start-console.bat`。会弹出一个黑色窗口，几秒后浏览器自动打开控制台。
- 想要桌面图标：在 PowerShell 里运行一次（只在你自己想要时运行，控制台不会自己创建）：

  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\create-desktop-shortcut.ps1
  ```

  桌面上会出现 "qbkb Console"，以后双击它就行。
- 会用命令行的话：`uv run qbkb console`（`--no-browser` 不自动开浏览器，`--port` 换端口）。
- 已经开着一个控制台时再双击，会直接打开已有的那个页面，不会开第二个。
- **停止**：关掉黑色窗口，或者点页面右上角的「退出」。

## 3. 四个页面

### 浏览文章
- 左边是目录，按类别分组，每篇显示中文标题、日期和分数；点一篇，右边显示译文。
- 右上角可以切换「中文」和「中英对照」（每段英文后面跟中文）。
- 顶部是原文链接、分数、类别和翻译时间。专业术语第一次出现时后面附英文，例如"趋势跟踪（trend following）"。
- 这里显示的就是知识库文件本身（`output\` 文件夹里的 `.md` 文件），也可以用别的 Markdown 软件打开。

### 运行
- 填"这次最多处理 N 篇"，点「运行」。下面会实时显示进度（发现 → 抓取 → 抽取 → 筛选 → 翻译 → 导出）和日志。
- 同一时间只能跑一个任务；跑的时候可以点「停止」，进度都保存了，下次接着跑。
- 跑完会显示结果：

  | 结果 | 意思 | 怎么办 |
  |---|---|---|
  | 正常完成 | 都处理好了 | 去「浏览文章」看新文章 |
  | 额度用完 | DeepL 或 DeepSeek 的额度用完了 | 进度已保存；DeepL 等下个月额度恢复后再点运行 |
  | 后端暂时不可用 | 限流或网络问题 | 过一会儿再点运行 |
  | 有文章需要处理 | 有的文章失败了或需要复查 | 看「待复查」页 |

- 真实模式下还会显示 DeepL 本月剩余额度（免费账户每月 100 万字符，一篇文章大约 2 万多字符）。

### 待复查
- **需复查**：翻译后检查发现结构对不上（脚注、图片、表格等），旁边有「重翻」按钮，点了只重翻这一篇，翻完自动发布。
- **失败**：抓取、抽取、翻译或导出出错，原因写在旁边（例如"HTTP 404：页面不存在"）。

### 设置
- **API key**：填 DeepL（翻译）和 DeepSeek（打分）的 key，点「保存 key」。key 只存在这台电脑项目文件夹的 `.env` 文件里，页面上只显示"已配置（末 4 位 xxxx）"。「测试连接」只查额度 / 模型列表，不花钱。
- **模式**：自动 / 演示 / 真实（见下一节）。「清空演示数据」只清演示模式的数据。
- **每天自动更新**：打开开关、选时间（默认 09:00）和每次最多几篇（默认 5），点「保存」。控制台会在 Windows"任务计划程序"里建一个叫 `qbkb-daily-update` 的任务；那个时间电脑没开机的话，开机后会尽快补跑。关掉开关就删除这个任务。不需要开着控制台，也不会弹窗口。页面上显示"上次自动更新：时间、结果、新增几篇"。

## 4. 演示模式和真实模式

| | 演示模式 | 真实模式 |
|---|---|---|
| 什么时候 | **没有填 key 时默认就是**（页面顶部有黄色提示） | 两个 key 都填好后自动切换；也可以在设置里手动选 |
| 文章从哪来 | 仓库自带的 4 篇示例文章（为演示自己写的，不是真实文章），在本机起一个小网站提供 | 真实的博客网站 |
| 打分 / 翻译 | 假的打分、自带的中文（不联网、不花钱） | DeepSeek 打分、DeepL 翻译（花额度） |
| 数据存在哪 | `.qbkb\demo\`（和真实数据完全分开） | 项目文件夹的 `state.db`、`output\` |

演示模式里特意安排了几种情况，方便看清每个页面：
- 一篇会被判成"ESG / 气候"、一篇属于排除的栏目：被筛掉，不翻译；
- 一篇页面不存在（404）：出现在「待复查」的"失败"里；
- 一篇第一次翻译时脚注会"丢掉"：出现在「待复查」的"需复查"里，点「重翻」就好了；
- 第一次「运行」选 2 篇、第二次再选 10 篇，可以看到增量更新（已经处理过的不再处理）。

想从头再演示一遍：设置 → 「清空演示数据」。

## 5. 常见情况

- **双击后窗口一闪就没了 / 提示 uv was not found**：第 1 步的 uv 没装好，或者装完没重新打开窗口。
- **浏览器没自动打开**：手动打开 `http://127.0.0.1:8790`（端口被占用时会换成 8791…，看黑色窗口里写的地址）。
- **页面提示"token 不对"**：控制台重启过，刷新一下页面。
- **真实模式点运行提示要先填 key**：到设置页填好两个 key；只想看看效果就切回演示模式。
- **提示"术语表数量到上限"**：DeepL 免费账户同时只能有 1 份术语表。qbkb 会自动删掉自己的旧版本；如果还有别的术语表（别的程序建的），到 DeepL 网站的账户里删掉不用的那份再运行。
- **自动更新没跑**：看设置页的"上次自动更新"；详细日志在 `logs\auto-update.log`（演示模式在 `.qbkb\demo\logs\`）。电脑睡眠 / 关机时会在开机后补跑。
- **有文章一直在"失败"里**：原因写在旁边；页面打不开（404）的文章不会自动消失，属于正常情况。
- **版权**：译文只在本机生成，**不要上传到公开的地方**（公开仓库里只有代码）。


## 离线表格输出（v2）

`qbkb table --site man --out output` 从现有状态库重建 `output/tables/man.csv`（UTF-8 BOM）和 `man.jsonl`。`qbkb export` 和默认 `run` 也会同步该站点的表格。每个站点独立文件，指定一个站点不会覆盖其他站点文件；快照读取该站点全部符合条件的已抽取记录，不受本次导出的篇数限制影响。

一篇一行，提供英文标题、中文标题、网址、英文 Markdown 正文、中文 Markdown 正文、发布时间、中文摘要、作者、标签、公司名，以及栏目、抓取时间、质量提示、翻译状态。CSV 将多行正文正确引用；JSONL 的标签和质量提示保留数组。未选栏目不输出；已翻译、已发布、待复查的下游历史记录仍保留，即使栏目后来取消采集或旧记录尚未补记栏目，避免隐藏已经花费额度的成果。未迁移的 extracted / filtered 不输出；尚未翻译或存在缺失/不合格译文时中文正文留空，不输出半篇译文，后者标记 `incomplete`。

本步骤不联网、不请求翻译或 LLM。中文摘要由独立的 `summarize` 命令生成；尚无可复用摘要且未运行或失败时留空，不使用英文description冒充中文。新成功保存的HTML记录可靠UTC抓取时间；旧行不推断回填，304不刷新抓取时间。旧行该字段留空，不能用最后更新时间替代。表格不属于可公开提交内容，沿用 `output/` 的忽略规则。


## 独立中文摘要加工

`qbkb summarize --site man --limit 10` 使用 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL（与现有 DeepSeek 配置一致）生成摘要。这是需要主动运行的独立加工命令，默认 `run` 不调用。运行后执行 `qbkb table --site man` 更新表格中的中文摘要。

成功摘要按实际正文与标题指纹、模型、接口地址、提示词和输入上限缓存；重复运行不会重复请求。正文或标题变化后旧摘要不再出现在表格里。摘要失败只记 summary_error，保留正文仍匹配的已有成功摘要，不改变采集/翻译状态；没有key时明确报错。额度耗尽返回3、限流/服务不可用返回4，稍后执行同一命令恢复，已成功的自动复用。

默认最多输入24000个正文字符（不含保留的版权附录），长文只概括可见部分，输出会显示截取计数，数据库保留 summary_truncated，并在表格质量提示中标注“摘要仅基于截取的正文”（不修改原始qc_issues）。可用 `--input-chars` 调整；调整会改变缓存版本。空输出、明显非中文、缺少完整结尾或被模型截断的输出不会缓存为成功摘要。源站description质量不稳定，本轮不用于生成主输入或伪装成中文摘要。新成功保存的HTML会记录UTC抓取时间，旧行时间未知保持为空。
